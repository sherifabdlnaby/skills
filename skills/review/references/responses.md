# Review comments on the user's PR

Covers: judging each comment, escalation, handing off to git.

Fetch the round, then post the replies, through the **git** skill's review-responses mechanics. This page decides what each reply says.

- **Judge each comment as a finding** at the level (default `balanced`):
  - You would raise it: fix it.
  - You would not: push back, and state the cost that makes it not worth it.
  - It asks to break a coding rule: push back and name the rule.
- **Merit, not authority.** Bots and AI-written comments are often right on mechanics and wrong on context; push back freely. A person gets more room on design and taste.
- **Escalate a real design tradeoff** a person raised. Attended: bring it to the user with the options, and leave the thread unanswered until they decide. Unattended: leave it open and list it in
  the report.
- **Status-only comments** (a passing quality gate, a bot summary with no request) need no reply.
